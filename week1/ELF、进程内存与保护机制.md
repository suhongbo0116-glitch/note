**一、 文件中的 ELF vs 运行中的进程**

| 对比项  | ELF 文件（磁盘上）     | 运行中进程（内存里）        |
| ---- | --------------- | ----------------- |
| 存在形式 | 静态文件，存放在磁盘      | 操作系统加载到内存中运行的实例   |
| 地址   | 文件偏移（从0开始）      | 虚拟地址（由 loader 分配） |
| 内容   | 代码、数据、符号表、重定位表等 | 只有运行需要的段被映射到内存    |
| 大小   | 包含调试信息、符号表等额外数据 | 只映射需要的 segment    |

**二、 Section vs Segment：链接视角 vs 装载视角**

| 对比项  | Section（节）          | Segment（段）        |
| ---- | ------------------- | ----------------- |
| 视角   | 链接视角：编译器/链接器用       | 装载视角：操作系统加载器用     |
| 划分依据 | 按功能分组（代码、只读数据、可写数据） | 按权限分组（可读可执行、可读可写） |
| 数量   | 很多（几十个）             | 很少（几个）            |
| 对应工具 | readelf -S（节头表）     | readelf -l（程序头表）  |

**三、常见 section 的用途**

| Section | 用途                  | 权限    |
| ------- | ------------------- | ----- |
| .text   | 存放编译后的机器指令（代码）      | 可读可执行 |
| .rodata | 只读数据：字符串常量、const 变量 | 只读    |
| .data   | 已初始化的全局变量（有初值的）     | 可读可写  |
| .bss    | 未初始化的全局变量（自动初始化为0）  | 可读可写  |

**四、进程内存布局与权限**

| 内存区域              | 内容                | 权限        |
| ----------------- | ----------------- | --------- |
| 代码段 (.text)       | 程序指令              | R-X 可读可执行 |
| 只读数据 (.rodata)    | 字符串常量、const 变量    | R-- 只读    |
| 全局数据 (.data/.bss) | 全局变量              | RW- 可读可写  |
| 堆 (heap)          | 动态分配的内存（malloc）   | RW- 可读可写  |
| 栈 (stack)         | 函数参数、局部变量、返回地址    | RW- 可读可写  |
| 共享库映射             | libc.so 等动态库代码和数据 | R-X / RW- |

**五、静态链接 vs 动态链接**

| 对比项   | 静态链接            | 动态链接                        |
| ----- | --------------- | --------------------------- |
| 做法    | 库函数代码直接拷贝进可执行文件 | 运行时加载 libc.so，通过 PLT/GOT 调用 |
| 文件大小  | 大（几MB）          | 小（几十KB）                     |
| 启动速度  | 快               | 慢一点（要加载动态链接器）               |
| 内存占用  | 每个进程都有一份库代码     | 多个进程共享同一份 libc 代码           |
| 查看方式  | ldd 无输出         | ldd 显示依赖的 .so 文件            |
| 动态链接器 | 不需要             | /lib64/ld-linux-x86-64.so.2 |

**六、PLT 和 GOT 的作用**

| 对比项 | PLT（过程链接表）     | GOT（全局偏移表）  |
| --- | -------------- | ----------- |
| 位置  | .text 段（可执行）   | .data 段（可写） |
| 内容  | 跳转指令           | 函数/变量的真实地址  |
| 作用  | 跳板，第一次调用触发动态解析 | 存真实地址，缓存    |
| 特点  | 每个外部函数有一项      | 对应每个外部函数    |

**七、文件偏移 vs 运行时虚拟地址**

| 对比项   | 文件偏移              | 运行时虚拟地址              |
| ----- | ----------------- | -------------------- |
| 含义    | 从 ELF 文件开头数的字节数   | 进程内存中的地址             |
| 起点    | 0x0               | 0x400000（No PIE）或随机化 |
| 关系    | 不一定相等，一般有固定差值     | 文件偏移 + 基址 = 虚拟地址     |
| 为什么不同 | .bss 不占磁盘空间，段对齐要求 | 由 loader 决定加载位置      |

**八、常见保护**

**1、NX（No eXecute）栈不可执行**

| 项目   | 说明                               |
| ---- | -------------------------------- |
| 作用   | 栈和堆上的内存页标记为不可执行，shellcode 不能直接运行 |
| 原理   | CPU 页表 NX 位，不可执行内存执行到就崩溃         |
| 绕过方式 | ROP：利用程序里已有的代码片段（gadget）拼接调用     |

**2、Canary（栈溢出保护）**

| 项目   | 说明                                      |
| ---- | --------------------------------------- |
| 作用   | 函数返回地址前放随机值，返回前检查是否被改                   |
| 原理   | 函数入口存 canary 在栈上，返回前对比，变了就终止            |
| 开启效果 | 栈溢出覆盖返回地址时必然覆盖 canary，程序崩溃              |
| 绕过方式 | 信息泄漏泄露 canary 值 / 找不检查 canary 的函数 / 暴力猜 |

**3、PIE**

| 项目   | 说明                                 |
| ---- | ---------------------------------- |
| 作用   | 程序加载基址每次随机，.text/.data 等所有段地址都变    |
| 原理   | 编译为位置无关代码，加载时内核选随机基址               |
| 开启效果 | 不知道 system、/bin/sh、gadget 的地址，没法写死 |
| 绕过方式 | 信息泄漏先泄漏一个地址算出基址 / 找固定地址 gadgets    |

**4、ASLR（地址空间布局随机化）**

| 项目   | 说明                           |
| ---- | ---------------------------- |
| 作用   | 操作系统级随机化：栈、堆、libc、共享库加载地址都随机 |
| 原理   | 内核在进程启动时随机选择各区域加载基址          |
| 开启效果 | 不知道 libc 基址、栈地址、堆地址          |
| 绕过方式 | 信息泄漏：先泄漏一个 libc 地址算出 libc 基址 |

**5、RELRO（重定位只读）**

| 项目            | 说明                                      |
| ------------- | --------------------------------------- |
| 作用            | GOT 表保护，防止通过 GOT 覆写劫持程序流程               |
| Partial RELRO | .got.plt 可写，.got 只读，可以改 got.plt 里的函数地址  |
| Full RELRO    | 所有 GOT 启动时解析完毕，整个 GOT 段标记为只读            |
| 绕过方式          | Full RELRO 下不能覆写 GOT，只能用 ROP / ret2libc |

**6、Fortify**

| 项目   | 说明                                           |
| ---- | -------------------------------------------- |
| 作用   | 对危险函数（gets/strcpy/memcpy等）做编译期长度校验           |
| 原理   | 用 __builtin___strcpy_chk 等 fortified 版本替换原函数 |
| 绕过方式 | 溢出长度不触发检查 / 找没有 fortify 的函数                  |

**总结**

| 保护      | 保护什么              | 怎么绕               |
| ------- | ----------------- | ----------------- |
| NX      | 栈上 shellcode 不能执行 | ROP               |
| Canary  | 栈溢出覆盖返回地址         | 泄漏 canary 值       |
| PIE     | 程序基址固定            | 泄漏程序地址算基址         |
| ASLR    | libc/栈/堆地址固定      | 泄漏 libc 地址算基址     |
| RELRO   | 改 GOT 劫持流程        | Full RELRO 下用 ROP |
| Fortify | 危险函数溢出检测          | 找未 fortified 的函数  |
